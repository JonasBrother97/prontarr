# Internationalization

The interface defaults to English. Use the language selector in the header to switch to Brazilian Portuguese. The preference is saved locally in the browser; missing, corrupt, unsupported or blocked storage falls back to English. Switching languages does not reload the page or change any download policy.

Translations use i18next and react-i18next. Catalogs are bundled in `frontend/src/locales/en.json` and `pt-BR.json`; no external translation service or runtime translation request is used. English source phrases are stable flat translation keys. `legacy.json` maps historical Portuguese backend messages to those keys so existing saved plans and events can be displayed in either language without rewriting the database.

Native Arr titles, release names, profile names and user-entered text are preserved. Dates, numeric sizes and title sorting use the selected locale. Machine identifiers and API enum values remain stable. The Zig backend emits English messages for new events and responses; the frontend localizes those messages at display time. React escapes rendered text.

When adding a UI message, add the same key to both catalogs and use `t()`. Use interpolation for dynamic sentences and keep variable names identical across catalogs. The frontend tests verify catalog parity, interpolation variables, safe language restoration and legacy message compatibility. Backend or policy changes are not required to add a UI translation.

References: [react-i18next](https://react.i18next.com/latest/usetranslation-hook) and [i18next interpolation](https://www.i18next.com/translation-function/interpolation).
